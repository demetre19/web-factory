# PATTERNS INDEX — the mined composition library

Every pattern node is a mined composition with prevalence and evidence:
`patterns/<site>/<section>/<pattern-id>.md`, frontmatter
`id: pattern-<site>-<page>-<section>-<composition>`, `type: pattern`,
`section_type`, `composition`, `speech_acts`, `n`, `prevalence`,
`evidence`, `implies_rules`, `enforced_by`, `used_in`,
`links: {index: patterns-index, composition: section-catalog#<slug>}`.

A pattern exists only when a cell has **n ≥ 10** annotated screens and a
gene subset reaching **≥ 60% prevalence** (`TAXONOMY.md` §5). Anything
else stays a cell with no pattern row — no placeholder patterns.

The table below is generated by `patterns/tools/build_patterns.py`; it is
the lookup surface for W2 (option proposals) and W5 (composition picks).
A composition with no pattern row has no evidence and cannot be chosen
(P.3/P.4). Query it with `tools/design-gate/patterns.py search`.

## How to read a row

- **n** — annotated screens behind the pattern; the evidence count, not a
  guess.
- **Prevalence** — share of the cell's screens that carry the signature
  allele set. 0.60 is the floor; hero cells sit near it because heroes
  genuinely vary.
- **Enforced by** — the `check_*` gate functions that police the genes in
  the signature. A pattern with no check is advisory only.

## Related nodes

- `patterns-taxonomy` — the cell grid and annotation schema.
- `section-catalog` — the closed composition set a pattern must cite.
- `design-genome` (`dna/GENOME.md`) — the genes and alleles the
  signatures are expressed in.
- `scorer-patterns` — turns a pattern match into a predicted-quality
  score (`patterns/VALIDATION.md` records how well it predicts).
