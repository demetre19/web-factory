# SB — Section-unit build and mechanical glue

**GOLDEN RULE: ASTRO is the goal; TAILWIND is non-negotiable.** A page
is never written in one pass. It is a plan row → a contract → one
section component → one page file that a script assembles. The model
touches a section; the script touches the glue.

Full architecture: `SECTION-BUILD.md` (node `section-build`).

### SB.1 Contract per plan row

Every row of `pages.<slug>.sections[]` gets exactly one
`sections/<nn>-<sec>.contract.json`, generated by
`python3 tools/design-gate/gate.py contracts <pipeline-dir>` — never
hand-written.

The contract carries: `section`, `index`, `wf_ref`, `composition`,
`archetype`, `speech_act`, `category`, `surface`, `density`,
`emphasis`, `align`, `stack`, `collapse`, `media_ratio`, `disclosure`,
`content` (verbatim `heading`, `fs`, `body`, `h1` from the STUB),
`neighbours` (prev/next surface + composition), `allowed` (classes +
token utilities), `rules`, `patterns`, `exemplar`.

**Enforcement** — script `check_section_contracts` @ w5. Threshold: one
contract per plan row, and every field above present and equal to the
plan row it came from. A missing or drifting contract blocks W3.

### SB.2 The shell owns rhythm

`Section.astro` is the only component that sets outer padding,
background, max width and gutters. It takes `sec`, `comp`, `wf-ref`,
`ratio`, `disclosure`, `surface`, `density` and emits
`<section class="sec-band" data-sec data-comp data-ratio
data-disclosure data-surface data-density>` around a `.sec-inner`
container.

A section component (`src/components/sections/<Sec>.astro`) MUST NOT
render its own `<section>` wrapper, `py-*`/`px-*`/`my-*`/`mx-*` outer
spacing, `bg-*` background, or `max-w-*` container. It renders content
inside the shell.

**One implementation, two layers.** The skeleton of a composition lives
once in `src/components/<composition>.astro` (P.6 — the component the
system tile instantiates). The section instance binds its plan row's
verbatim content and renders that component:
`<SplitMedia heading=… fs=… />`. A section instance that re-writes the
skeleton instead of rendering the component is a duplicate design and
fails.

**Enforcement** — script `check_section_shell` @ w6, reading the
instance plus every component it imports. Threshold: zero outer-layout
declarations in either file; `exemplar:` present; the instance renders
`<Component />` for its row's composition. Spacing between sections is
then impossible to get wrong.

### SB.3 One builder per section, one gate per section

W6/W7 fan out: one builder agent per section, given only its contract,
the matching card, the tokens and the components — nothing else. The
builder returns one component. It passes
`python3 tools/design-gate/gate.py section <pipeline-dir> --sec <name>`
before the page exists.

**Enforcement** — script `check_section_gates` @ w6. Threshold: every
contract has a `sections/<nn>-<sec>.gate.json` with `pass: true`, and
every section file passes `check_section_allowed` (only contract
classes/token utilities, no color literals, no arbitrary `[...]`
values).

### SB.4 The glue is mechanical

`python3 tools/design-gate/assemble.py <pipeline-dir>` writes
`site/src/pages/<slug>.astro` from plan order: imports each section,
wraps it in `<Section>` with the plan's surface and density. No model
edits that file.

**Enforcement** — script `check_assembly` @ w7. Threshold: page file
exists, its `<Section>` sequence equals plan row order, every row's
component is imported, and the `assembled:` marker hash equals the hash
of the current contracts (hand edit ⇒ stale marker ⇒ FAIL).

### SB.5 Gold exemplars, adapted not invented

Each composition archetype has one approved reference component in
`templates/sections/<composition>/`. A section builder adapts the
exemplar to its content and tokens instead of inventing a layout. The
composition node in the graph links to its exemplar.

**Enforcement** — script `check_exemplars` @ w6. Threshold: every
composition used by the plan has an exemplar file, and every section
component names it (`exemplar: <composition>` in frontmatter).

### SB.6 Page gates only after section gates

W7–W8 run page-level rhythm, PS segmentation, scorecard, speed, mobile
and the full-page reviewer rubric. A page-level failure names its
section (or the plan row); the fix re-runs that unit and the glue —
never the whole page.

**Enforcement** — script `check_scorecard` @ w8 plus the per-section
`gate.json` trail. Threshold: scorecard sections ≥ 90%, and any FAIL
row resolves to a plan row or a section gate record.
