## 4. Methodology critique

**What matches real practice.** Discovery → moodboard/references → visual direction → design system → content → structure → components → pages → QA is the order mature studios use (and the order Figma-first teams follow: style tiles/element collages before page comps; tokens before components). Making the system sheet the first approved artefact, deriving variants as token deltas on one system, and locking structure as data (`data-*` rows) before build are all correct and stronger than most agency process.

**Where it diverges from how designers actually work, and from operator intent.**

1. **Content after look is backwards for a content-dictates-layout law.** W2 (look) and W3 (system lock + DNA v1) happen before W4 (content). Real content-first practice (and the operator's "content dictates layout") inventories content before committing type scale, density and section padding, because content length drives measure, density tier and hero type size. With DNA locked at W3, any content that needs an off-map value forces a full DM.6 rebuild. Fix: move the content inventory into W1 discovery (it already extracts headings/keep-list) and make W4 a verification wave, or keep W4 but let W3 lock only stylistic knobs while structural knobs (`section_py`, gutter, type.base) lock at W5 after content.
2. **Structure is chosen twice.** DESIGN-INTAKE "Phase B direction cards" (structure + type scale in one greyscale card, operator picks) and W5 wireframe cards (structure from content, operator picks) both decide structure; W2 tiles decide look. Designers separate *look* (style tiles) from *structure* (wireframes) exactly once each. Delete the intake Phase B structure decision or define it as W5 input.
3. **Wildcard/burst at W5 is the wrong place.** A wildcard *structural* option at the wireframe stage combined with structural-tier breakability (F-04) re-opens the exact failure the lock exists to stop. Real studios put the "exploratory" option in the look stage, not in the locked structure. Restrict wildcard to W2 stylistic knobs.
4. **The gate is graded by the graded.** Every independence mechanism (approval flag, REVIEW.json reviewer string, variant `pass`, section `*.gate.json`) is a file the designer agent can write (F-01, F-07, F-08). Real design QA is independent because a different person signs. The machinery needs one trust boundary: artefacts the designer can write vs records only the operator/reviewer process can write (separate directory, hash-bound to inputs, verified by the gate).
5. **Labels instead of renders.** The lock is enforced on attribute strings (`data-comp`), not on what is rendered. Designers compare comps side by side visually; the mechanical equivalent is per-section structural fingerprints (DOM shape of the exemplar archetype, grid columns at 1280/768/360, media ratio) diffed card ↔ page, plus a screenshot diff of greyscale card vs a greyscaled render of the built page at the same viewport. Without that, F-05/F-06 recur.
6. **Too many reviewer rules for an AI reviewer.** 43 reviewer-mode rules, many measurable (F-28). An LLM reviewer is the weakest grader in the chain; every rule that can be computed should be, leaving the reviewer only genuinely perceptual items (intent legibility, focal payoff, coherence).
7. **Meta-gates measure bookkeeping.** coverage/consistency/graph/selftest all pass while waves deadlock (F-02) and the lock is breakable (F-04). Add an end-to-end golden pipeline fixture (a tiny site that must pass W0→W8 via `run.py`, and a set of mutants — page reordered, wrong composition, tile/page token drift, self-approval, empty shots — that must each fail at the expected wave). That is the only test that proves the machinery, as opposed to its parts.
8. **Mobbin as a gate, not a ritual.** Real reference research ends in annotated boards tied to decisions. Require MOBBIN-REFS rows to cite which DNA field / composition each reference informed, and have DNA v0 `provenance` link to them; otherwise the step is satisfiable by pasting one URL (F-20).
